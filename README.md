# 世界计划固车助手（Sekai Guche Assistant）

面向《世界计划：缤纷舞台！ feat. 初音未来》/《初音未来：缤纷舞台》/ *Project SEKAI: Colorful Stage!* 玩家的 **固车群自动拾取车牌** 小工具（下称「固车助手」）。

在固车群（打歌互助房）里，有人发出房号（5 位数字）时，机器人自动把这串数字写进群名，方便固车群友快速上车，并支持前后缀、严格/宽松匹配、冷却防刷、改名记录查询等。附带 **WebUI**，开箱即用，不用改代码就能改配置。

> 记录你的每一次冲榜：改名历史可查、可导出，冲线那一刻的车牌都在。

---

## 功能一览

| 模块 | 说明 |
|------|------|
| 自动拾取车牌 | 群内出现 5 位数字房号时，自动更新群名 |
| 前缀 / 后缀 | 车牌放在群名最前或最后，可按群单独设置 |
| 严格 / 宽松 | 严格：只认纯 5 位数字；宽松：消息开头提取 5 位（后面可带备注） |
| 群内指令 | 开启 / 关闭 / 帮助 / 模式切换，均可配置指令文案 |
| 权限 | 开启、关闭、改模式需管理员；改名本身所有人可触发 |
| 冷却 | 按群冷却（默认 5 秒），防止刷屏改名 |
| 群名保护 | 超长自动截断（保留车牌），并提示「群名过长已截断」 |
| 改名记录 | 按群保存历史，WebUI 可按日期查询、删除、导出 JSON |
| WebUI | 浏览器管理：配置、群组、统计、实时日志，本地即开即用 |
| 双模式 | 独立运行（OneBot 反向 WS），或作为 NoneBot2 插件（`nonebot-plugin-sekai-guche/`） |

## 快速开始

### 1. 准备

1. 一台能长期开着的电脑（Windows / Linux）
2. 已部署 **OneBot V11** 实现（任选其一即可，与本程序无关）
3. 机器人账号进入需要启用的固车群，并具备 **修改群名** 权限

### 2. 获取程序

- 从 [Releases](https://github.com/Shinonome-ena/guche/releases) 下载 `guche.exe`（Windows）
- 或自行编译（见下文「从源码构建」）

将 `guche.exe` 与 `config.default.json` 放在同一目录，复制一份并改名为 `config.json`。

### 3. 在 OneBot V11 客户端里添加网络配置

本程序通过 **OneBot V11** 协议与机器人前端通信：guche 监听**反向 WebSocket**，由 OneBot V11 客户端主动连上来。

请打开你所使用的 OneBot V11 客户端，进入**网络配置**，新建一条 **WebSocket 客户端**（有的实现叫「反向 WebSocket」），按下面填写：

| 配置项 | 填写 |
|--------|------|
| 类型 | WebSocket 客户端 / 反向 WS |
| 地址（URL） | `ws://127.0.0.1:8901/ws` |
| 消息格式 | **array**（消息段数组，不要用 CQ 码字符串） |
| Token（若启用） | 与 `config.json` 的 `onebot.token` 一致，或留空 |
| 重连 | 建议开启 |

说明：

- 端口必须与 `config.json` 里 `onebot.port` 一致（默认 `8901`）。
- 路径是 **`/ws`**，不是根路径。
- 这里是「客户端连向 guche」，不是 guche 去连 OneBot。
- 各家 UI 叫法略有差别，认准：**WebSocket 客户端 + 反向** 即可。

### 4. 启动

```powershell
.\guche.exe
```

- 反向 WS：`ws://127.0.0.1:8901/ws`（以配置为准）
- 管理界面：`http://127.0.0.1:8080`（以配置为准）

启动后在目标群发送（默认指令）：

```text
/开启固车拾取
```

即可开始自动拾取车牌。发送 `/固车拾取 使用方法` 查看群内帮助。

## 群内指令

| 默认指令 | 作用 | 权限 |
|----------|------|------|
| `/开启固车拾取` | 启用本群自动改名 | 管理员 |
| `/关闭固车拾取` | 关闭本群（未启用时静默） | 管理员 |
| `/固车拾取 使用方法` | 显示帮助 | 所有人 |
| `/固车模式` | 查看当前模式与设置说明 | 管理员 |
| `/固车模式 前缀` / `后缀` | 车牌位置 | 管理员 |
| `/固车模式 严格` / `宽松` | 匹配方式 | 管理员 |
| `/固车模式 前缀 严格` | 同时设置两项 | 管理员 |
| 发送 5 位数字 | 自动写入群名 | 所有人（已启用的群） |

只改一项时不会动另一项；例如全局是「前缀 宽松」，单独设成「后缀」后，匹配仍是宽松。

### 匹配示例

| 消息 | 严格 | 宽松 | 说明 |
|------|------|------|------|
| `12345` | ✅ | ✅ | 纯 5 位 |
| `12345 来车` | ❌ | ✅ → `12345` | 开头 5 位 |
| `123456` | ❌ | ❌ | 6 位不认 |
| `abc12345` | ❌ | ❌ | 必须以数字开头 |

### 群名规则

- 群名超过 **60** 字时自动截断，优先保留车牌，并在回复中说明
- 前缀模式会替换旧的「开头 5 位数字」；后缀模式会替换旧的「结尾 5 位数字」

## WebUI

浏览器打开 `http://127.0.0.1:8080`（端口以配置为准，仅监听本机）。

| 页面 | 功能 |
|------|------|
| 概览 | WS 连接状态、启用群数、今日/累计改名 |
| 群组管理 | 添加/删除群、前后缀与严格宽松（可单字段修改）、同步群名、恢复默认 |
| 配置编辑 | 机器人地址与端口、token、指令文案、全局模式、冷却、管理员、缓冲区等 |
| 统计详情 | 今日/累计/区间次数，按群查看改名记录，按日期删除、导出 JSON |
| 实时日志 | 运行日志（完整到秒的时间戳），可筛选 |
| 帮助 | 使用说明 |

配置在 WebUI 修改后会立即生效，并写回 `config.json`，下次启动仍在。

## 配置说明（config.json）

```json
{
  "onebot": {
    "host": "127.0.0.1",
    "port": 8901,
    "token": null
  },
  "admin_users": [],
  "commands": {
    "guche_enable": "/开启固车拾取",
    "guche_disable": "/关闭固车拾取",
    "guche_help": "/固车拾取 使用方法",
    "guche_mode": "/固车模式"
  },
  "guche": {
    "fuzzy": false,
    "pos_end": false,
    "cooldown_seconds": 5.0,
    "groups": {}
  },
  "stats": {
    "max_records_per_group": 1024
  },
  "webui": {
    "enabled": true,
    "port": 8080
  },
  "buffers": {
    "log_buffer_size": 1024,
    "message_queue_size": 512,
    "connection_pool_size": 10
  }
}
```

| 字段 | 含义 |
|------|------|
| `onebot.host` / `port` | OneBot V11 反向 WS 监听地址；**填什么端口就用什么端口**，被占用会报错而不会静默换端口 |
| `onebot.token` | 可选。设置后连接需带 `Authorization: Bearer <token>` 或 `access_token` |
| `admin_users` | 固车助手管理员列表（插件内指令权限，非群聊管理员；OneBot `user_id`）；**空数组 = 所有人都能用管理指令** |
| `guche.fuzzy` | 全局匹配：`false` 严格，`true` 宽松 |
| `guche.pos_end` | 全局位置：`false` 前缀，`true` 后缀 |
| `guche.groups` | 已启用群表：**键存在 = 已启用**；`pos` / `mode` 为 `true` / `false` / `null`（跟随全局） |
| `stats.max_records_per_group` | 每群保留的改名记录条数上限 |
| `webui.port` | 管理界面端口（只绑 `127.0.0.1`） |

`config.default.json` 为可随包分发的默认模板；本地运行时的实际文件为 `config.json`（已加入 `.gitignore`，不会上传仓库）。

## 从源码构建

```powershell
git clone https://github.com/Shinonome-ena/guche.git
cd guche
cargo build --release
```

产物：`target\release\guche.exe`（Windows）/ `target/release/guche`（Linux）。

运行测试：

```powershell
cargo test --workspace
```

### 目录结构

```text
guche/
├── crates/
│   ├── guche-core/     # 纯逻辑：匹配、改名、权限、冷却（无 I/O）
```

## Docker（适合服务器 / NAS）

家用 Windows 直接用 exe 即可；要挂在服务器上时可用官方镜像（linux/amd64 + arm64）：

```bash
cp config.default.json config.json
# 编辑 config.json 后：
docker compose up -d
```

或手动运行：

```bash
docker run -d --name guche \
  -p 8901:8901 -p 8080:8080 \
  -v ./config.json:/app/config.json \
  -v ./data:/app/data \
  ghcr.io/shinonome-ena/guche:latest
```

OneBot V11 客户端的反向 WS 填 `ws://<宿主机IP>:8901/ws`。镜像由打 `v*` 标签时的 GitHub Actions 自动构建并推送。

## 常见问题

**Q: 启动后 OneBot 客户端连不上？**  
检查反向 WS 的 `url` 端口是否与 `config.json` 的 `onebot.port` 一致，消息格式是否为 `array`，以及防火墙是否放行本机回环。

**Q: 发了 5 位数字没改名？**  
确认：本群已 `/开启固车拾取`；不在冷却中；匹配模式（严格/宽松）是否符合消息形态。

**Q: WebUI 改了设置群指令不生效？**  
二者写入的是同一份群配置（`guche.groups`），保存后立即生效。若用旧版配置文件（`match_mode` / `group_position` 等旧字段名），请改成 `fuzzy` / `pos_end`。

**Q: 端口被占用会怎样？**  
会直接报错退出对应服务，**不会**自动改到其它端口，避免和 OneBot 客户端对不上。
